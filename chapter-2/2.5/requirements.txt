# 【为什么本文件过去要求单独建虚拟环境，现在不用了】
#
# 书稿把 langchain 钉在 1.1.0，在那个前提下 2.5 节确实装不进主环境，
# 原因有三层，且第三层是确定性故障：
#
#   第一层  deepagents 0.3.x 要求 langchain-core>=1.2.5，与 1.1.0 冲突。
#   第二层  deepagents 依赖 langchain-anthropic，后者要求 anthropic>=0.120.0；
#           而 vllm==0.13.0 精确钉死 anthropic==0.71.0 —— 二者无交集。
#           （已实测复现：pip 直接报 ResolutionImpossible）
#   第三层  langchain 1.1.0 只允许 langgraph<1.1.0，最高到 1.0.10；
#           而 langgraph 1.0.10 声明 langgraph-prebuilt>=1.0.8,<1.1.0，
#           该窗口内 1.0.9 / 1.0.10 都写着
#               from langgraph.runtime import ExecutionInfo, ServerInfo
#           但 langgraph 1.0.10 的 runtime.py 里根本没有这两个名字
#           （1.0.11~1.0.13 又要求 langchain-core>=1.3.1，被 1.1.0 排除）。
#           pip 在可行范围内取最新 = 1.0.10 = 坏的，于是
#               ImportError: cannot import name 'ExecutionInfo'
#           波及全书 22 个 `from langchain.agents import create_agent`。
#
# 把 langchain 上调到 1.4.x 后，三层同时消失：
#   * langchain-core 1.6.9 满足 deepagents 0.7.23（要求 >=1.6.7）；
#   * vllm 已移出根配方（它无 Windows wheel、全书 0 个文件 import 它），
#     anthropic 得以升到 1.13.0，满足 langchain-anthropic 1.7.5；
#   * langchain 1.4.4 允许 langgraph>=1.2.11,<1.3.0 → 1.2.14，
#     其 runtime.py 第 27/61 行正是 ExecutionInfo / ServerInfo 的定义，
#     与 langgraph-prebuilt 1.1.0 的导入完全对上。
#
# 实测：在全新隔离目录真实安装本配方后，16 项导入测试全部通过
# （含 create_agent、langgraph.prebuilt、deepagents 两条 API）。
# ============================================================================

# deepagents 经 langchain-anthropic 间接需要；显式写出以便复现
